# AGENTS.md — правила работы с .NET Courses

Этот файл — инструкция для AI-агентов и участников, которые создают уроки, задания, квизы, редактор и сайт. Перед изменениями читать **этот файл**, README.md, _config.yml и соответствующие существующие уроки. Если структура или пользовательские договорённости изменились, сначала свериться с текущим репозиторием и журналами. Не использовать устаревший формат из старых записей Google Docs вместо актуального Jekyll-сайта.

## 1. Цель и педагогические принципы

- Аудитория: **опытный C#/.NET-разработчик**. Объяснять не только синтаксис, но и проблему, ограничения, альтернативы и применимость.
- Выбирать **полезные для рабочих задач** темы, а не проходить весь changelog или перечень API ради галочки. Приоритет: применимость, частота использования, выигрыш в понятности/производительности и возможность короткой практики.
- Строить **связанные учебные цепочки**. Использовать общий развивающийся пример несколько занятий, возвращать уже изученные идеи в новых условиях. Если тема большая, делить её на несколько уроков подряд.
- Примеры — небольшие, реалистичные и переносимые в сервисный код: обработка HTTP-метрик, импорт записей, парсинг, коллекции, форматирование, JSON, потоки, буферы. Не усложнять учебное задание настройкой инфраструктуры.
- Для обеих программ — **не более 30 минут на занятие, включая повторение**. Ориентир: 4 мин повторение, 8 мин теория + 1–2 кратких примера, 12 мин самостоятельный код, 4 мин проверка, 2 мин вывод. Если не помещается — разделить тему или провести занятие на закрепление.
- Каждый новый приём подкреплять одним-двумя старыми. Использовать перекрёстные ссылки на конкретные опубликованные уроки **в обе стороны**; рядом со ссылкой кратко напомнить нужную идею, чтобы не заставлять перечитывать весь урок.
- Не включать Aspire, MAUI, F#, WPF, WinForms без отдельного изменения программы.
- Язык уроков и навигации — **русский**; имена API и термины C# писать корректно. Не делать общих заявлений вроде «любой struct лежит в стеке» или «Span/params/ValueTask всегда исключает аллокации».

## 3. Различия между программами

**Курс «Что нового в C#/.NET»:**
- Период: C# 13–15 и .NET 9–11. Проверять стабильность конкретной фичи, требования SDK, языка и TFM; preview обозначать явно и не выдавать за стабильную возможность.
- Когда есть две действительно ценные взаимосвязанные темы, можно объединять языковую C# и платформенную .NET. **Не требовать две новинки каждый день**, если одна не приносит пользы.
- Опорные цепочки: коллекции и LINQ, улучшения API и прочие практические нововведения. Не повторять пройденное без учебной цели.

**Курс «Память и аллокации»:**
- Идти по программе `ALLOC-001 … ALLOC-045` (ID — **темы, не календарные дни**); адаптировать темп по практике.
- Явно различать **heap-аллокации, копирование данных, удержание памяти, работу GC и CPU**. Любую заявленную оптимизацию подтверждать измерениями; не делать вывод о выигрыше из синтаксиса.
- Последовательные практические линии: разбор записи `ORD-1042;paid;1499.90` (это простой заданный формат, **не общий CSV**), структура результата заказа, формирование буферизованного вывода, потоки и JSON.
- Цепочка `readonly` — **девять отдельных связанных тем**, а не один обзор: readonly-поля; readonly struct/record struct; value/ref/in; defensive copies; readonly-члены; ref readonly-возврат/локальная переменная; обход ref readonly; ref readonly-параметры; readonly-представление и отличие от immutable-данных. После базы можно углублять scoped, ref struct, буферы.
- По возможности возвращаться к приёмам соседнего курса (`params ReadOnlySpan<T>`, `CountBy`, `AggregateBy`), но показывать новый аспект затрат и реальные компромиссы.

## 4. Обязательная структура каждого урока

Использовать существующую Jekyll collection и layout `lesson`. Для каждого урока:

1. **Заголовок и front matter**: порядковый номер **внутри своего курса**, реальная дата публикации, `title`, `summary`, `csharp_feature`, `dotnet_feature`, `series`; для памяти — `topic_id` (ALLOC-XXX). При поддерживаемом браузерном запуске — `browser_runtime` (сейчас `'9'` или `'10'`). Пример существующего front matter читать перед созданием следующего.
2. **Проблема**: короткий рабочий сценарий, зачем механизм нужен, когда не нужен.
3. **Краткая теория**: синтаксис, ограничения, стоимость, безопасные альтернативы, версия API и статусы stable/preview.
4. **Минимальные запускаемые примеры**: 1–2 коротких фрагмента плюс **цельная рабочая программа**, версия C#/SDK/TFM, команды запуска, **ожидаемый вывод**. Примеры должны компилироваться, а не быть псевдокодом, если не обозначены как фрагменты.
5. **«Напиши код сам»**: небольшое самостоятельное задание (обычно 10–12 минут), конкретная сигнатура/заготовка **без реализации**, входные данные, ожидаемый результат, критерии, один-два пограничных случая. Подсказка доступна отдельно, **не раскрывает полное решение**. Не подменять задачу копированием метода из объяснения.
6. **Проверки с Assert**: автоматические проверки именно реализации пользователя (см. следующий раздел), а не только вывод нескольких значений на экран.
7. **Повторение и связь**: вопросы с постоянными Q-ID, ссылка на квиз своего курса, 1–2 перекрёстные ссылки на опубликованные темы (где это полезно), краткий вывод и возможное продолжение цепочки.
8. **Источники**: ссылки на официальную документацию Microsoft (для бенчмарков — BenchmarkDotNet), относящиеся к фактически изученной версии.

- Показывать полные уроки на **сайте**, не присылать простыню текста или отдельный скачиваемый HTML в чат. После успешной публикации — короткое описание и рабочая ссылка.
- Когда пользователь просит первый урок, **сначала сверить программу и последний номер соответствующего курса**. Не перезаписывать предыдущий урок; не выставлять задним числом отметку «освоено».
- Для HTML в Markdown: в `<textarea>` экранировать `<` и `>` как `&lt;` и `&gt;`, иначе C# generics и другие символы могут сломать разметку. Следить за корректными ID и data-practice-id.

## 5. Практика и настоящие Assert (обязательное требование)

У каждой самостоятельной задачи — **исполняемый проверочный harness** в браузерном запуске:

- Кнопка **«Запустить моё решение в браузере»** собирает компилируемую программу из стартовой сигнатуры/кода пользователя и тестового окружения; реальные тесты вызывают **именно его метод**, а не демонстрационную или скрытую эталонную реализацию.
- Тесты включают типичный случай, **пустой ввод**, пограничный/ошибочный случай; при необходимости — регистр, порядок сортировки, точность или владение памятью. Фактические ожидания должны соответствовать условию.
- Использовать явный `Assert` с понятным сообщением: например, `if (!condition) throw new Exception("TASK-XXX: причина");` или вспомогательный метод `Assert(bool condition, string message)`. **Не полагаться только на Debug.Assert**, который может быть исключён из Release-компиляции.
- При успехе — ясная строка о прохождении тестов; при ошибке — сообщение, объясняющее нарушенное условие. Проверять не только что код компилируется, но и что он возвращает нужные значения.
- **Не раскрывать готовое решение** в публичной заготовке или в тестовом обвязочном коде. Не считать прохождение автотестов достаточным подтверждением понимания/производительности; после присылки кода в чат дать ревью.
- Тестовые данные и ожидаемые значения заранее просчитать и проверить независимым запуском. Для задач производительности Assert проверяет **корректность**, а аллокации/скорость сравнивать отдельным корректным бенчмарком, не пороговым Assert по времени.
- Если браузерный компилятор пока не поддерживает API, не заявлять о браузерном запуске: дать локальный runnable .NET-проект, команды и тесты, и явно описать ограничение.

## 6. Интерфейс редактора и сохранение черновиков

- **Каждый C#-пример** на странице, который предлагается запустить, должен иметь кнопку «Запустить этот пример». Для неполного фрагмента адаптер `browser-snippets*.js` добавляет окружение для компиляции, **не искажая исходный фрагмент на странице**. Синхронизировать число примеров с `exampleCount` адаптера.
- В отдельной видимой панели **на странице урока над iframe** обязательно иметь **«Запустить текущий код»**, «Копировать весь код» и «Скачать Program.cs». Команда запуска берёт **текущий отредактированный текст из редактора**, а не повторно загружает демонстрационный пример. Ctrl+Enter — дополнительный способ, но не единственный.
- Отдельно различать «Сохранить решение из редактора в задание» (перенос только фрагмента задания) и сохранение **всего Program.cs**. Если маркеров задания нет, объяснить, что открыт пример, и предложить копирование/скачивание полного кода вместо технической ошибки без пояснения.
- Черновики кода и ответов хранятся **локально в браузере** (localStorage) с ключами, разделяющими курсы, задания и уроки; при обновлении страницы должны восстанавливаться. Рядом с редакторами показывать **понятный статус автосохранения/восстановления или ошибки**. Не утверждать, что код сохраняется на сервере или автоматически попадает в Google Docs.
- Не очищать черновики из-за публикации новой версии сайта, смены кеша/URL ресурсов или запуска другого примера. При полной замене кода пользователя предупреждать/сохранять возможность экспорта.
- Если опубликованный сайт показывал устаревшую страницу из HTTP-кеша: учитывать `sw.js`, revision из сборки, cache-busting CSS/JS и ограничения HTTP-заголовков GitHub Pages. **Новый HTML уроков/квизов/главной должен загружаться свежим, но локальные ответы не должны стираться**. Не пересобирать WebAssembly для изменения текста страницы или JS-оболочки.
- Не притворяться, что браузерный компилятор предоставляет полноценный семантический IntelliSense или автоматически обновляет личный журнал.

## 7. Вопросы, интервальные повторения и личный журнал

- Вопрос — **самостоятельная единица повторения** с постоянным уникальным Q-ID и Topic-ID. Несколько аспектов темы — несколько вопросов. Типы: концепция, анализ кода, прогноз результата, исправление ошибки, сравнение.
- Публичные банки: `_data/questions.yml` и `_data/memory_questions.yml`; не объединять курсы. Схема существующих записей: `id`, `topic`, `tag`, `type`, `available_from`, `prompt`. **Без правильных ответов и без личной истории**.
- В коротком квизе обычно **4–6 вопросов**; первыми — ошибки и просроченные вопросы, когда история известна. Не раскрывать ответ до попытки. Поле для ответа, копирование и экспорт в .txt должны работать.
- Последовательные **правильные** ответы на конкретный вопрос: интервалы **1, 3, 7, 14, 30, 60 дней** (затем 60). Ошибка и частичный ответ → повтор на следующий день со сбросом серии. **Пропущенный вопрос/нет ответа — не ошибка**.
- Только **после фактического ответа пользователя** оценивать вопрос, объяснять ответ и фиксировать дословный ответ, дату, оценку, серию и next_due в соответствующем личном Google Doc. Нельзя выдумывать ответы, оценки, выполненный код, результаты проверок и посещение урока.
- Отдельные статусы: **урок опубликован/показан**, **практика назначена/прислана/проверена**, **конкретный вопрос отвечен и оценён**. Публикация не означает прохождение. ID не переиспользовать даже после исправления текста вопроса.

## 8. CI/CD, WebAssembly и проверка перед публикацией

- Единый pipeline: `.github/workflows/pages.yml`, публикация GitHub Pages по push в main. Публикацию считать выполненной только **после успешных build + deploy** и проверки нужной страницы. При ошибке читать журнал job/step и устранять причину.
- **WebAssembly-компиляторы .NET 9 и .NET 10 кешируются отдельно**. Ключи зависят от закреплённого upstream MicrosoftLearning/c-sharp-minor, скрипта подготовки и конкретного стартового файла для каждой версии. Пересобирать только при изменении реальных зависимостей или промахе кеша; не выполнять тяжёлый `dotnet publish` на каждый Markdown/CSS/JS-коммит.
- При необходимости сборки готовить **независимые копии исходников** для .NET 9 и .NET 10: скрипт изменяет файлы и повторное применение к уже изменённым исходникам приводило к ошибкам.
- GitHub Actions уже использует выпуски с поддержкой Node.js 24. Не откатывать их к версиям с предупреждением о Node.js 20.
- Для каждого нового урока проверять: (а) корректную Jekyll-разметку/front matter; (б) ссылки, навигацию и квиз соответствующего курса; (в) компиляцию и **ожидаемый вывод** C# с нужным SDK; (г) **работающие Assert на пользовательском методе**, включая проверку, что заведомо ошибочная реализация не проходит; (д) запуск каждого демонстрационного примера через адаптер; (е) запуск **отредактированного** кода; (ж) копирование/скачивание, сохранение и восстановление черновиков; (з) корректный вывод на светлой/тёмной теме, на узком экране.
- Синтаксис JS проверять через `node --check`, C# — через `dotnet build/run`, Jekyll — через фактическую сборку. При добавлении урока расширять smoke-тесты workflow и проверять, что опубликованы ожидаемые HTML-страницы. Не считать незавершённый workflow успехом.
- Для Markdown/Jekyll ссылок применять `relative_url` с учётом `baseurl: /dotnet-courses`. Изменения маршрутов не должны молча ломать перекрёстные ссылки и кнопки.
- При правке кеширования следить за тем, чтобы страницы и задания показывали новые версии, но **черновики не удалялись**. Большой WASM runtime может кешироваться отдельно от HTML и JS.
- Если действие зависит от отсутствующего инструмента или прав доступа, прямо сказать, что удалось/не удалось проверить. **Не обещать фонового завершения**; при ответе указывать текущий статус.

## 9. Конфиденциальность и стиль ответа

- Репозиторий **публичный**. Никогда не добавлять реальные ответы, попытки, оценки, частные данные, токены, служебные URL, корпоративный код или секреты пользователя в GitHub, логи сборки или клиентские скрипты.
- Google Docs хранит приватную историю. Обновлять только после реальных событий; соблюдать точные ссылки, ID и даты. Не терять существующий журнал ради нового формата.
- После публикации в чате: **короткая законченная карточка** с темой, практической целью и проверенной ссылкой. Не копировать туда весь урок; вопросы задавать только действительно необходимые.
- Прежде чем менять архитектуру или запускать автоматизацию для второго курса, сверить, что пользователь действительно поручил её создать. Существующая автоматизация курса нововведений **не должна случайно публиковать задания в курс памяти или дублировать выпуски**.

## 10. Краткий чеклист нового урока

- [ ] Тема выбрана по реальной пользе, найдена её связь с соседними уроками; проверены план, ID и версия .NET/C#.
- [ ] ≤30 минут со всем повторением; короткое объяснение и реальные, запускаемые C#-примеры с ожидаемым выводом.
- [ ] Самостоятельная функция с заготовкой, входом, критериями, границами и необязательной подсказкой **без решения**.
- [ ] Для функции есть **исполняемые Assert** на основные и пограничные случаи; неверная реализация их не проходит.
- [ ] Каждый обещанный C#-пример запускается; редактор запускает **текущую правку**; кнопки копирования/скачивания и перенос задания работают.
- [ ] Черновики локально сохраняются и восстанавливаются; это явно указано рядом с полями.
- [ ] Вопросы с новыми постоянными ID в **правильном банке**; приватные ответы и ключи не опубликованы.
- [ ] Перекрёстные ссылки и навигация ведут в нужный курс; URL обновлены без устаревших путей.
- [ ] Smoke-тесты/CI обновлены и пройдены, WebAssembly не пересобирается без необходимости, Pages deploy подтверждён.
- [ ] Журнал обновлён **только достоверными** статусами публикации/практики/ответов; пользователю дана короткая ссылка.
