## Как добавить урок с кодом

Примеры, ожидаемый вывод и заготовку задания храни в Markdown урока. Укажи в начале файла `code_framework`, например `net11.0` в уроке 003.

| Что написать в Markdown | Как используется |
| --- | --- |
| Блок `csharp` и сразу за ним `{: #snippet-full-program }` | Сайт показывает этот код. CI компилирует и запускает его. |
| Блок `text` и сразу за ним `{: #output-full-program }` | Сайт показывает ожидаемый вывод. CI сравнивает с ним результат запуска. |
| Блок `csharp` и сразу за ним `{: #practice-program }` | Полный `Program.cs` задания, включая исходные `Assert`. Заготовку пометь строками `// BEGIN TASK-ID` и `// END TASK-ID`, в её теле оставь `throw new NotImplementedException();`. |
| `<script type="text/plain" id="practice-wrong-body">` | Между открывающим и закрывающим тегами запиши только заведомо неверное тело вместо заглушки. Теги ставь на отдельных строках. CI подставит тело в копию задания и проверит, что исходный `Assert` обнаруживает ошибку. |

Для каждого запускаемого примера используй свой суффикс. Например, блоку `#snippet-countby` соответствует `#output-countby`. Обычные поясняющие фрагменты оставляй без этих меток. Пример урока со всеми блоками — [урок 003](_lessons/003-ordered-dictionary-extension-indexers.md).

### Браузерный запуск

Для браузера добавь `browser_runtime` и `browser_start_snippet` с суффиксом стартового примера, например `full-program`. Выбирай профиль для версии `code_framework`.

| `browser_runtime` | Среда выполнения | Язык |
| --- | --- | --- |
| `'9'` | .NET 9 | C# 13 |
| `'10'` | .NET 10 | C# 14 |
| `'11'` | .NET 11 | C# 15 |

Полную программу с `Program.Main` редактор откроет напрямую. Если отдельному короткому фрагменту нужно окружение, укажи файл `browser_snippets` и добавь обработчик для этого фрагмента.

Кнопка «Запустить этот пример» загружает и выполняет пример урока. «Запустить текущий код» выполняет открытый код вместе с правками. Запустить его можно и через Ctrl+Enter из редактора. Кнопка «К выводу» переводит фокус в консоль. На широком экране консоль расположена справа от кода, на узком — под редактором.

Редактор берёт стартовый метод и полный `Program.cs` с `Assert` из блока `#practice-program`. «Открыть заготовку» или «Открыть черновик» загружает программу. Чтобы проверить свой метод, используй «Запустить текущий код».

## Pipeline

Общий скрипт [`verify_lessons.cjs`](_browser/verify_lessons.cjs) находит уроки в обеих коллекциях. Он создаёт временные проекты для указанных версий .NET, проверяет вывод примеров, компилирует заготовки и запускает неверные варианты. С установленными SDK уроков запусти `node _browser/verify_lessons.cjs` из корня репозитория. Для проверки одного урока передай путь к его Markdown.

Pull request в `main` запускает проверки GitHub Actions. GitHub Pages публикуется после успешных проверок на `main`. Каждый профиль WebAssembly кешируется отдельно. Ключ зависит от закреплённого исходника компилятора и скрипта подготовки. Код урока редактор получает со страницы, поэтому при попадании в кэш правка статьи обходится без пересборки WebAssembly.

Settings → Pages → Build and deployment → Source: **GitHub Actions**.

Публичный адрес — [boyarincev.net/dotnet-courses](https://boyarincev.net/dotnet-courses/).

Не помещайте в публичный GitHub рабочие секреты, конфиденциальные исходники, личные ответы и историю интервальных повторений. Черновики хранятся локально в браузере; персональный журнал курса ведётся в Google Docs.

## Квиз и прогресс

Интервальное повторение на сайте использует **ts-fsrs@6.0.0 (FSRS-7)** с адаптивными интервалами. У каждого вопроса есть постоянный `Q-ID`, привязка к `lesson_number` и отдельная карточка FSRS с историей и сроком следующего повторения. Ссылка `?through=N` формирует короткую подборку из текущего и предыдущих уроков. Состав подборки и самооценки сохраняются при перезагрузке. При прямом открытии квиз охватывает весь курс.

После заполнения ответа ученик ставит «Неверно», «Частично», «Верно» или «Легко», и FSRS пересчитывает срок. Данные хранятся в браузере. JSON-копия квизов переносит черновики ответов, расписание и историю FSRS и отметки о пройденных квизах.

## Идеи дальнейшего развития

1. **«Предскажи результат и запусти».** Ученик записывает ожидаемый вывод короткого C#-примера, запускает код и открывает объяснение. Для первого варианта достаточно одного фрагмента из опубликованного урока и локального поля для прогноза. Подойдут случаи, где легко ошибиться в порядке вычисления, выборе перегрузки или при работе со структурами.
2. **«Что повторить сегодня».** На странице курса показать число вопросов, срок которых уже наступил по FSRS, и кнопку короткой сессии. После нескольких ответов показать, сколько вопросов осталось на сегодня. Каждый курс использует свой банк и свою историю.
3. **Сравнение двух реализаций.** Запускать варианты A и B на одинаковом вводе и показывать их вывод рядом. Начать с одного упражнения, где варианты отличаются по наблюдаемому поведению. Для курса памяти можно дополнительно скачать проект BenchmarkDotNet, чтобы отдельно измерить время и аллокации в локальной среде.
4. **Единая резервная копия курса.** Добавить к истории квиза черновики C#, последние успешные решения и отметки о прохождении практики. Перед импортом показывать, какие данные будут добавлены или заменены. Файл остаётся у ученика.
