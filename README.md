## Как добавить урок с кодом

Примеры, ожидаемый вывод и заготовку задания храни в Markdown урока. Укажи в начале файла `code_framework`, например `net11.0` в уроке 003.

| Что написать в Markdown | Как используется |
| --- | --- |
| Блок `csharp` и сразу за ним `{: #snippet-full-program }` | Сайт показывает этот код. CI компилирует и запускает его. |
| Блок `text` и сразу за ним `{: #output-full-program }` | Сайт показывает ожидаемый вывод. CI сравнивает с ним результат запуска. |
| Блок `csharp` и сразу за ним `{: #practice-program }` | Полный `Program.cs` задания, включая исходные `Assert`. Заготовку пометь строками `// BEGIN TASK-ID` и `// END TASK-ID`, в её теле оставь `throw new NotImplementedException();`. |
| `<script type="text/plain" id="practice-wrong-body">` | Между открывающим и закрывающим тегами запиши только заведомо неверное тело вместо заглушки. Теги ставь на отдельных строках. CI подставит тело в копию задания и проверит, что исходный `Assert` обнаруживает ошибку. |

Для каждого запускаемого примера используй свой суффикс. Например, блоку `#snippet-countby` соответствует `#output-countby`. Обычные поясняющие фрагменты оставляй без этих меток. Пример урока со всеми блоками — [урок 003](_lessons/003-ordered-dictionary-extension-indexers.md).

### Браузерный запуск

Для браузера добавь `browser_runtime` и `browser_start_snippet` с суффиксом стартового примера, например `full-program`. Выбирай профиль для версии `code_framework`.

| `browser_runtime` | Среда выполнения | Язык |
| --- | --- | --- |
| `'9'` | .NET 9 | C# 13 |
| `'10'` | .NET 10 | C# 14 |
| `'11'` | .NET 11 | C# 15 |

Полную программу с `Program.Main` редактор откроет напрямую. Если отдельному короткому фрагменту нужно окружение, укажи файл `browser_snippets` и добавь обработчик для этого фрагмента.

Кнопка «Запустить этот пример» загружает и выполняет пример урока. «Запустить текущий код» находится сразу под кодом и выполняет его вместе с правками. Рядом расположены краткий статус запуска и «Открыть в .NET Lab». Запуск доступен и через Ctrl+Enter. В обычном режиме код занимает всю ширину редактора, а консоль с выводом и подробностями ошибок находится под ним.

Иконка рядом с заголовком «Редактор C#» разворачивает редактор вместе с консолью. В полноэкранном режиме консоль находится справа на широком экране и под кодом на узком. Esc переводит фокус из кода к кнопке запуска. Повторное нажатие в полноэкранном режиме сворачивает редактор. «Копировать весь код» и «Скачать Program.cs» находятся отдельной строкой под редактором и консолью, обратная связь выводится рядом с ними.

Если Roslyn указал место ошибки в `Program.cs`, нажми на сообщение в консоли. Редактор выделит соответствующий фрагмент исходника. После правки запусти код заново, чтобы получить ошибки для текущей версии.

Редактор берёт стартовый метод и полный `Program.cs` с `Assert` из блока `#practice-program`. «Открыть заготовку» или «Открыть черновик» загружает программу и переводит к началу кода. Над редактором видны условия зачёта и статус урока. После прохождения исходных `Assert` появляется ссылка «Пройти квиз урока».

## Pipeline

Общий скрипт [`verify_lessons.cjs`](_browser/verify_lessons.cjs) находит уроки в обеих коллекциях. Он создаёт временные проекты для указанных версий .NET, проверяет вывод примеров, компилирует заготовки и запускает неверные варианты. С установленными SDK уроков запусти `node _browser/verify_lessons.cjs` из корня репозитория. Для проверки одного урока передай путь к его Markdown.

Pull request в `main` запускает проверки GitHub Actions. GitHub Pages публикуется после успешных проверок на `main`. Каждый профиль WebAssembly кешируется отдельно. Ключ зависит от закреплённого исходника компилятора и скрипта подготовки. Код урока редактор получает со страницы, поэтому при попадании в кэш правка статьи обходится без пересборки WebAssembly.

## Публикация

Settings → Pages → Build and deployment → Source: **GitHub Actions**.

Публичный адрес — [boyarincev.net/dotnet-courses](https://boyarincev.net/dotnet-courses/).

Не помещайте в публичный GitHub рабочие секреты, конфиденциальные исходники, личные ответы и историю интервальных повторений. Черновики кода, ответы и сроки повторения хранятся локально в браузере.

## Квиз и прогресс

Интервальное повторение использует **ts-fsrs@6.0.0 (FSRS-7)**. У каждого вопроса есть постоянный `Q-ID`, привязка к `lesson_number` и своя история оценок. По ссылке `?through=N` квиз показывает вопросы урока N без оценённого ответа, по одному за раз. После ответа и самооценки на все вопросы квиз показывает итог и даёт скачать или скопировать ответы. Если в урок добавится вопрос, квиз предложит ответить на него при следующем открытии.

«Повторить сегодня» (`?review=today`) показывает вопросы с наступившим сроком. После зачёта практики вопросы без карточек получают первый срок повторения через восемь часов. Банк вопросов открывается по адресу квиза без ограничения по уроку. Фильтр `?filter=completed` показывает вопросы пройденных уроков, `?filter=all` — всего курса, `?filter=N` — урока N.

Резервная копия доступна на странице курса. Файл JSON включает расписание и историю FSRS, черновики кода, последние успешные решения и отметки о прохождении практики. Импорт рассчитан на текущий формат копии того же курса и применяется после подтверждения.

## Идеи дальнейшего развития

1. **«Предскажи результат и запусти».** Ученик записывает ожидаемый вывод короткого C#-примера, запускает код и открывает объяснение. Для первого варианта достаточно одного фрагмента из опубликованного урока и локального поля для прогноза. Подойдут случаи, где легко ошибиться в порядке вычисления, выборе перегрузки или при работе со структурами.
2. **Режим сравнения двух реализаций.** Добавить два поля для кода, общий набор входных данных и кнопку «Сравнить». Для каждого входа показывать результаты A и B рядом. В курсе памяти время и аллокации можно сравнивать локально через BenchmarkDotNet.
